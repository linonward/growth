## 0. 先说清楚：门禁没有通过

| 门禁 | 阈值 | 现状 |
| --- | --- | --- |
| D8+ 回访率（9–12 岁段） | ≥ 25–30% | **无数据**（尚未招募） |
| 6–8 岁能否独立进入闭环 | 家长介入率 ≤ 70% | **无数据** |
| 「行为 → 世界变化」是否被看到 | `stages_seen` 分档 + 延迟回忆 | **无数据** |

Phase 0 的产出是**一套可判读的测量底座**（13 个已合并的 PR）与**一份执行协议**，
不是结论。**现在开始 Phase 1，是主动跳过门禁，不是通过门禁。**

这个选择本身是允许的 —— 但它必须被写下来，因为它的代价是具体的：

> 的代码，而是产品定位。**「孩子为世界变化而回来」这条一旦不成立，
> 整个长期化路线（成长、图鉴、长期线）都是在为一个不存在的动机做工程。

## 1. Phase 1 的三个候选方向（先选一个，不要都做）

README 末尾列了七个候选，但它们回答的是**三个完全不同的问题**。
选错方向的成本，比做慢一点大得多。

### A. 「7 天之后」——长期成长

> 问题：**第 8 天之后，世界还能怎么变？**

现在 Day 7 讲完一个完整故事，孩子回来发现"没有新东西了"。Phase 1 最小的一块就是
让这个世界**能继续**：新的成长阶段、长期线、慢变量。

- 直接服务的假设：**产品是否可能长期存在**（Phase 0 只证明了 7 天）
- 代价最小的切口：把"结束"改成"继续"——Day 7 之后不再是终章，而是一个转折
- 风险：如果 Phase 0 的 D8 回访很低，说明孩子**根本不想回来**，
  那长期化是在给一个没人要的东西加内容

### B. 「家庭层」——让家长有价值，但不接管孩子

> 问题：**家长凭什么持续投入（设备、时间、钱）？**

`docs/competitive-positioning.md` 已经诚实承认：**家长价值弱**是当前最大竞争劣势
（没有家长端、没有成长曲线，而"给家长看数据"常常是家长买单的理由）。

- 直接服务的假设：**可持续性**（谁来为它付费/续期）
- 代价，也是红线：**家长端不能变成监督面板**（P4 的整个存在理由）。
  能做的是"孩子主动分享"，不是"家长随时查看"
- 这一条**尤其需要 Phase 0 的家长旁证数据**：现在没人知道家长到底在意什么

### C. 「更深的世界」——内容与自定义（含皮肤）

> 问题：**世界的吸引力能不能不靠"新解锁"来维持？**

多宠物、多地图、世界搭建、皮肤都属于这一支。

- 直接服务的假设：**动机结构**（是探索/拥有，还是解锁）
- 这里藏着一个会毁掉实验的分叉：**皮肤/图鉴如果靠"完成目标解锁"，
  那就是换了名字的积分商城**，直接把 Phase 0 的结论作废
- 所以这一支必须先回答：**拿什么换？**答不出来就别做
  → 已开工：设计备忘见 [`ux-research/world-themes-design.md`](./ux-research/world-themes-design.md)
  （三个选项、工程量核查、以及我的默认建议：起始定制 + 只有两个主题、不解锁）

### 我的建议

**先做 A，但只做它的最小切口：把 Day 7 的"完整了"改成"还会继续"。**

理由是它是三者里唯一**同时**满足这三个条件的：

1. 它是 Phase 0 结论的**直接延伸**（不是新假设）；
2. 它的最小版本可以在一周内做完，且不引入代币、不引入家长端；
3. 它把 B 和 C 需要的**数据问题**提出来（家长为什么留下、世界怎么不靠解锁维持吸引），
   而不是先替它们做工程。

## 2. 无论选哪个，Phase 1 开工前必须补齐的四件事

这四件不是"最好有"，是**不做就一定会在中途付出更高代价**的：

| # | 事项 | 为什么现在做 | 代价 |
| --- | --- | --- | --- |
| 1 | **数据层从 `localStorage` 迁到服务端** | 长期成长意味着跨设备、跨清理；现在清一次浏览器数据 = 孩子的世界没了。这在 7 天实验里可接受，在长期产品里是**数据丢失** | 引入后端、账号（Phase 0 明确不做的东西），需要一起决定最小形态（匿名 device-id 还是登录） |
| 2 | **analytics schema 从 14 个事件松绑** | `ANALYTICS_EVENT_NAMES` 固定 14 个是为了防 Phase 0 范围蔓延。Phase 1 一定要新维度，这条纪律要改成"**新事件必须对应一个待验证假设**" | 一次性的纪律改写 + 评审流程 |
| 3 | **目标库要跟着年龄走** | 现在 11 条目标对 6 岁和 12 岁是同一套。评估 §2 已证明读不懂：6–8 岁读不了「有不会的问老师」。长期产品必须分龄 | 目标库结构从"平铺 11 条"变成"按年龄带分组"，测试也要跟着改 |
| 4 | **`experiment_version` 的语义要升级** | 现在它标记一次实验。长期产品里它要标记**产品版本**，否则 D8 数据和三年后的数据没法分池 | 一行常量背后的含义变更，要同步文档 |

> 第 1 项是真正的分水岭。**它把项目从"原型"变成"产品"**，也是 Phase 0 里
> 唯一一件被明令不做、且不能靠前端绕过的事。

## 3. 明确不做（Phase 1 也一样）

不管选哪一支，下面这些**到 Phase 1 结束都不要碰**，除非有数据支持：

- ❌ **任何形式的代币、积分、兑换、商城** —— 这是 Phase 0 要证伪的东西，
  在它没被证伪之前加回来，实验结论直接作废
- ❌ **排行榜、社交、比较** —— 对榜上靠后的孩子是负向激励（P4）
- ❌ **家长端变成监督面板** —— 只能做"孩子主动分享"，不能做"家长随时查看进度"
- ❌ **推送/提醒召回** —— SAAR 的意义就是"不靠提醒"，加了推送等于放弃这个指标
- ❌ **为 6–8 岁做纯文字界面** —— 评估 §2 已证明读不懂。要么加音频/图示通道，
  要么明确把 6–8 岁划出去

在开工前写下，事后不改：

```text

    ________________________________________________
```
