# 皮肤 / 世界主题：设计备忘（C 支开工前的门槛）

> 版本 `2026-09-21`。对应 [`../phase1-charter.md`](../phase1-charter.md) 的 C 支。
>
> 章程给 C 支设了一道门槛：**皮肤/外观一旦靠"完成目标解锁"，就是换了名字的积分商城，
> 会直接作废 Phase 0 的结论。** 所以这份备忘只回答一件事：**拿什么换？**

## 1. 三个真实选项（不是三个说法，是三种不同的动机结构）

### 选项 1：起始定制（推荐）

**在世界诞生时选一次，此后只能改、不能赢。**

- 位置：欢迎页之后、选伙伴之前（或之后），**一次点击，两个选项**
- 换什么：**不换任何东西**。它不花能量、不做任务、不解锁
- 动机结构：**所有权**（"这是我的岛"），不是收集
- 对实验的影响：**不影响**。孩子回来的理由仍然是"想看世界变成什么样"，
  主题只是他看它时戴的一副眼镜

### 选项 2：表达式成长（最有意思，也最贵）

**主题不是选出来的，是长出来的。**

- 例子：岛的长相取决于孩子**一直在做什么**——学习多的岛长出更多树，
  运动多的岛出现更多地形；或者 Day 7 之后岛按"你这一周的样子"分叉成不同形态
- 换什么：用**真实行为本身**换，不用代币。这是"世界因我而变"的加强版
- 动机结构：**能力感与自我表达**
- 代价：这不是皮肤系统的工程量，是**世界生成**的工程量；而且它要先有
  "长期使用"的数据才有意义（现在连 D8 都没有）

### 选项 3：解锁制（明确否决）

**完成目标 → 得星 → 攒够换皮肤。**

- 为什么看起来诱人：它有明确的进度条，能立刻增加"回来的理由"
- 为什么否决：**它就是代币制**。孩子回来的理由变成"想解锁下一个皮肤"，
  而不是"想看世界变化"——Phase 0 要证伪的正是前者。
  一旦这样，Pilot 的 D8 数据就**无法解释**：分不清是动机成立还是收集欲成立
- 除非：Phase 0 数据证明"世界变化撑不住动机"，**并且**我们决定改赌注。
  那是 Phase 2 的决策，不是现在

## 2. 工程量（我从渲染代码里核过的真实情况）

结论：**"加一个选择器"是这份工作里最小的部分。**

- `PALETTE`（`src/components/world/palette.ts`）**只有 4 个文件在用**：
  `WorldScene` / `Scenery` / `PetSprite` / `PlantSprite`。表面上很干净。
- 但这些文件内部还有 **21 处硬编码颜色**，而且都是**大面积**的：
  - `WorldScene`：**天空渐变** 3 段（`#9FD8FF` / `#CFEBFF` / `#F4FBFF`）—— 占屏幕 2/3
  - `Scenery`：**地面 5 层渐变**、云的白、石头高光、**彩虹门 5 条色带**、
    新区域的山丘/小溪/小屋、Day 4 的花
  - `PetSprite` / `PlantSprite`：精灵本体基本都在 PALETTE 里，但 `Scenery` 里的
    花和蝴蝶是硬编码的
- **所以只换 `PALETTE` 是行不通的**：地面、天空、彩虹不会变，孩子会看到一个
  **配色打架的世界**。真正的第一步是**把这 21 处收进 palette**——这本身就是
  一个独立的、可验证的重构 PR，而且它对"皮肤"零承诺（即使皮肤不做，它也值得做：
  现在想调一次地面颜色要翻三个文件）

**建议的拆分：**

| 步骤 | 内容 | 规模 |
| --- | --- | --- |
| 1 | 把 21 处硬编码颜色收进 `palette.ts`，**行为完全不变**（纯重构，e2e 图与断言保持） | 一个 PR，半天 |
| 2 | palette 变成"按主题取色"（`theme → colors`），默认主题 == 现在的颜色 | 一个 PR，半天 |
| 3 | **两个**精心配好的主题 + 首启一次选择 + 持久化 + 导出可见 | 一个 PR，一天 |
| 4 | （可选，等数据）主题 A/B 在协议里做对照 | 协议，不写代码 |

## 3. 为什么我的默认选项是"起始定制 + 只有两个主题"

1. **它不引入代币**，所以 Phase 0 的结论不会被污染。这是硬约束，不是偏好。
2. **"只有两个、不再增加"是刻意的。** 一个皮肤清单本身就是"要收集的东西"，
   哪怕免费，也会把注意力从世界变化移到收集上。两个选项足够回答
   "有没有所有权"，不足以形成收集行为。
3. **它便宜。** 步骤 1+2 无论如何都该做；真正属于"皮肤"的只有步骤 3。
4. **它可逆。** 如果 Pilot 显示孩子对主题毫无反应，删掉它不损失任何东西
   （第 1 步的重构仍然是有价值的）。

## 4. 这份设计**不**能验证什么（必须写明）

- 它**不会**回答"靠外观能不能维持留存"。因为不支持解锁，就没有"下一个皮肤"的拉力。
- 它**不会**回答"孩子会不会为了收集而回来"。那正是我们**故意不去制造**的行为。
- 它能回答的只有：**所有权/个性化对孩子有没有可观察的影响**——
  而且这个问题本身要靠协议（主题 A/B 对照），不是靠代码。

**如果 Pilot 的数据是："D8 很低" + 访谈里孩子说"看起来都差不多/不像我的"，
那才轮到选项 3 进入讨论。** 在那之前做解锁制，是在没有证据的情况下
把实验的解释力抵押出去。

## 4.5 决定：选了选项 3（解锁制）——记录在案

**2026-09-21，决策人选择选项 3。** 本仓库照做，并在此记录这笔交易：

| | |
| --- | --- |
| 货币 | **星星**（= 有行动的天数）。不是新货币，也不是能量 —— 用能量会让做得多的孩子成长变慢 |
| 价格 | 晴天 0 星 / 星空 1 星 / 秋天 2 星（阶梯序号即价格） |
| 解锁 | **永久**。已解锁的主题可自由换，不重复扣费（扣费换装对 6 岁孩子等于"东西被拿走了"，违反 P5） |
| 节奏 | 每天都行动的孩子在 **Day 2 和 Day 3** 各解锁一次 |
| 入口 | 首页「换个样子」，在星星园旁边；奖励第 4 段会说明解锁了什么 |
| 埋点 | **不新增事件**。主题存在 `profile` 里，导出自带 `profile.worldTheme` |

### 这笔交易的真实代价（必须写进任何用这份数据的报告）

**孩子回来的理由可能是"想解锁下一个主题"，而不是"想看世界变化"。这两个动机在留存数据里长得一模一样。** 因此：

- 本 build 的 **D8 回访率不能单独用来证明核心赌注**。它混入了收集驱动。
- 报告必须写明：本阶段同时引入了代币式解锁，D8 若要作为核心赌注的证据，需要与「无解锁」版本对照（或做 A/B）。
- 好的一面：货币是**已经存在**的星星，完成目标对世界的影响一行未变；因此 `goal_completed`、`stages_seen`、Day Gate 这些机制指标仍然可比。

## 5. 需要你拍的两个点

**① 已定：选项 3（解锁制）**，见 §4.5。

**② 主题名字与气质（已按中性描述词实现，可改）：**

```text
晴天 · 现在的样子（默认，0 星）
星空 · 天黑之后的世界（1 星）
秋天 · 叶子变黄的时候（2 星）
```

三者已在同一套明度/饱和度下核对过（见 PR 截图）：没有哪个明显"更好看"，
否则孩子只会选那一个，测到的就是审美而不是世界。
