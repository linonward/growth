# Pilot 执行协议（6–12 岁）

> 目的：把「招聘 → 设备录入 → 7 天使用 → D8 补导 → 访谈」变成一份**谁都照做得到**
> 的清单，让 16–20 户家庭的数据可以放在一起分析。
>
> 这份协议只做一件事：保证**评估文档里先写下的判据**能被真的读出来。
> 判据见 [`phase0-evaluation.md`](./phase0-evaluation.md) §8，本文不重复定义结论。

## 0. 实验前的一次性检查

| 检查 | 为什么 |
| --- | --- |
| `pnpm verify` 与 `pnpm e2e` 全绿，`main` 上就是准备跑实验的那一版 | 实验期间不要改代码。中途改版本 = 中途换刺激 |
| 线上 `growth.linonward.com` 打开的首页有欢迎页（不是直接进世界） | 确认部署的是 `origin/main`，且 `localStorage` 是空的 |
| 设备上**不要**带 `?debug=1` 交给孩子 | 面板会浮在底部挡住按钮（已知），而且实验者不该出现在孩子流程里 |
| 每台设备固定一个参与者 | 参与者身份是设备上的匿名 UUID。换设备 = 换人，数据无法合并 |
| 记录 `experiment_version`（当前 `phase0-v2`） | 混版本分析等于混两次实验 |

**每台设备准备一张卡片**，写上：

```text
参与者编号（实验者自己的编号，例如 P07）：
设备编号：
年龄带（6-7 / 7-8 / 8-9 / 9-10 / 10-11 / 11-12）：
开始日期（Day 1）：
Day 7 日期：
计划补导日期（Day 7 + 3 天）：
```

> **参与者编号只存在于这张卡片和导出文件名里。** 应用内部只有匿名 UUID，
> 不要把编号写进设备、也不要把姓名写进任何地方（见 README 的隐私一节）。

## 1. 样本与分层

**目标：5 个年龄带 × 3–4 户 = 16–20 户。**

| 年龄带 | 年级 | 目标户数 |
| --- | --- | --- |
| 6–7 | 一年级 | 3–4 |
| 7–8 | 二年级 | 3–4 |
| 8–9 | 三年级 | 3–4 |
| 9–10 | 四年级 | 3–4 |
| 10–12 | 五、六年级 | 3–4 |

> **不要报 6–12 的合并数字。** 混龄均值会把「低龄段整段动画没被看到」抹平成
> 「看起来正常」（这是 `pnpm analyze` 里已经防住的坑，报告里也要防）。

**协变量：** 每户填一份家长症状清单（§3.1）。目标用户里「走神、坐不住」的孩子和
高执行功能的孩子对同一产品反应完全不同；不控这个变量，**年龄效应会和行为特征混淆**。

**招募时就要分层的两个问题**（筛选问卷 §3.2）：孩子年级、以及家长是否认为孩子
"注意力/学习上有些困难"。后者决定这户属于哪一层的对照，不是排除标准。

## 2. 时间线（每户 4 次接触）

```text
T0  设备交接（10–15 分钟，实验者在场）
     └─ 录入年龄带 → 家长填症状清单 → 交给孩子 → 孩子自己完成欢迎页
T1  Day 1（当天或次日，电话/微信 5 分钟）
     └─ 只问两件事：孩子有没有自己再打开过？有没有卡在哪一步？
T2  Day 3–4（5 分钟，可选）
     └─ 只记录是否还在用。不要提醒、不要鼓励、不要问"今天做了吗"
T3  Day 7 之后（10 分钟）
     └─ 看孩子愿不愿意给家长看这个世界 → 家长 30 秒旁证（§3.3）
T4  Day 7 + 3 天（5 分钟，**必须**）
     └─ 补导一次数据（§4）。这是主验收点唯一能取到的地方
```

**实验者在整周里的唯一义务是「不要提醒」。** SAAR 测的就是"谁先想到打开"，
一句"今天打开了吗"就把这户的 SAAR 变成污染数据 —— 那比少一户更糟。

### T0 的具体动作（顺序不能变）

1. 孩子**不在场**时，用 `?debug=1` 打开面板，在「年龄组（实验者填写）」里选对应档位。
   面板会显示当前值，确认它不再是「未记录」。
2. 家长填症状清单（§3.1）。
3. 关掉 `?debug=1`，回到普通网址，把设备交给孩子。
4. **让孩子自己走完欢迎页。** 不解释、不代点。孩子问"这是什么"时，回答"你自己看看"——
   这正是 AC1（不看教程也能理解）要测的。
5. 只在孩子明显卡住超过 1 分钟时给一次最小提示，并**在卡片上记一笔**
   （`T0 提示：选目标`）。这类记录是"6–8 岁是否需要成人脚手架"的原始证据。

## 3. 三份工具

### 3.1 家长症状清单（一次性，约 2 分钟）

> 说明：这不是诊断，只用来在分析里区分"孩子本来执行功能如何"。
> **没有正确答案，也不会影响孩子看到任何内容。**

请按最近两周的情况，在每项后选：**从不 / 有时 / 经常**

1. 做事情（写作业、看书）时容易分心。
2. 需要反复提醒才能开始做一件事。
3. 坐不住，喜欢站起来走动。
4. 容易忘记刚交代的事情。
5. 完成任务比同龄孩子慢。
6. 遇到不会的题容易放弃。
7. 情绪起伏大，容易着急。
8. 能自己安排好看屏幕以外的时间。
9. 在学校被老师提过注意力或纪律问题。
10. 学习上目前有明显困难（哪一科：______）。

**分析口径：** 1–5 与 7 计为「执行功能负担」，8–9 反向计分。只做**分层标签**
（低 / 中 / 高），不做分数报告，不写进任何给家长看的东西。

> 如果后面要正式发表或给家长反馈，需要换成有版权许可与常模的标准化量表
> （如 SNAP-IV、SDQ），并补齐监护人知情同意。**本 Phase 0 不做这两件事**，
> 所以这里只用自编的轻量清单，且只用于内部分层。

### 3.2 筛选问卷（招募时，约 3 分钟）

1. 孩子年级？（→ 决定年龄带，**不是让孩子自报**）
2. 家里有没有一台孩子可以每天用的手机/平板？谁保管？
3. 这一周有没有考试、旅行、生病等会打乱日常的安排？（有 → 换一周开始）
4. 孩子平时用平板/手机做什么？大约每天多久？
5. 家长是否认为孩子在注意力或学习上有些困难？（是 / 否 / 不确定）
6. 家长能不能做到**这一周不主动提醒**孩子打开这个 App？
   （答"不能" → 仍可参加，但该户的 SAAR 单独标注、不进主分析）

### 3.3 家长 30 秒旁证（T3，只在 Day 7 之后一次）

> **只确认，不否认。** 没有"否"这个选项，也**不改变孩子的任何东西**（P5）。

```text
这一周里，孩子打开这个 App 的时候，通常是谁先起的头？
  [ ] 孩子自己拿出来就打开了
  [ ] 我或家人叫他/她来打开
  [ ] 我也不太确定
```

**用途：** 它是 SAAR 的校验列，不是替代品。孩子的自述在 §5.1 里已经改成中性问法，
这份旁证用来估计"被提醒 vs 被代开"的比例 —— 对 6–8 岁尤其关键。

**放在哪：** 实验者用纸或在 `/debug/export` 之外的入口记录，**绝不进孩子端流程**。

## 4. 数据导出（最容易做错的一步）

**每个参与者要导两次。**

| 时机 | 文件命名 | 作用 |
| --- | --- | --- |
| Day 7 当天（T3） | `P07-d7.json` | 周内行为、可信度信号、reward 观看 |
| **Day 7 + 3 天（T4）** | `P07-d11.json` | **D8+ 回访 —— 主验收点** |

为什么必须补导：`experiment_day` 被设计钳在 1–7（游戏里没有第 8 天），所以 D8 信号
来自 `session_started` 的**时间戳**。Day 7 当天导出的文件里 D8+ 一定是 0 ——
**那不代表孩子没回来，只代表文件取早了。** `/debug/export` 页面会在 D8+ 还是 0 时
提示这一点。

操作路径：设备上打开 `/debug/export` → `Download Experiment Data` →
把文件改名成上面的格式 → 立刻确认文件里 `age_band` 不是 `null`。

**导出页要核对的三个值：**

- `年龄组`：不是「未记录」。**这个值必须在孩子开始玩之前就录好**（§2 第 1 步），
  所以正常情况下不可能缺。如果发现是「未记录」，说明当时漏了：补填会写进导出和
  其后的事件，但**那次打开之前的事件仍然是 `null`** —— 这一户的 D1 数据要按
  「未分档」标注，不要假装它分过档，也不用为了它重跑一周。
- `第 8 天及以后回访`：Day 7 时是「还没有」（正常）；T4 时应该 ≥ 1 天
- `自主 / 被叫来 / 没回答`：三个数字之和应该等于"被问过的天数"

> **一个参与者有两个文件时，`pnpm analyze` 会把他算成两行。** 分析前先决定口径：
> 用 `-d11.json`（它包含周内 + D8 的完整事件），**不要**把两个文件都传进去。
> 传两个文件只适合快速核对两次导出是否一致。

## 5. 数据质量检查（每户导完立刻做）

```bash
# 用 T4 那一份（它含周内 + D8 的完整事件）。不要两个文件一起传，
# 那会把这个参与者算成两行。
pnpm analyze P07-d11.json
```

逐条核对：

1. **D8+ 回访那一节不是「无法判读」。** 若显示无法判读，说明这个文件里没有
   `postWeek` —— 那是旧版本导出的，需要更新设备上的版本。
2. **年龄组不是「未记录」。** 未分档的参与者**不能**用来支持任何分龄结论，
   报告里会单独成行并打印占比。
3. **可信度信号有没有 ⚠️。** 有 ⚠️ 不影响主验收点，但要在报告里标注：
   学校类目标的完成数据不能用来证明行为改变。
4. **reward 观看的 `stages_seen` 与 `skipped` 一起读。** 连点也能拿满分，
   只看段数会高估注意力。

## 6. 每次接触要问的定性问题（不要自由发挥）

**T1（Day 1 后）：** 只问"孩子有没有自己再打开过"和"卡在哪一步"。
**不要**问"喜欢吗"。

**T3（Day 7 后，孩子在场时，3 分钟延迟回忆探针）：**
完成当天目标 **20 分钟后**问：

> 「刚才小光做了什么？」

| 孩子的回答 | 说明 |
| --- | --- |
| 说得出"行为 → 世界变化"的因果 | 核心闭环在这一户成立 |
| 只记得"+10"或"有个动画" | 数值盖过了世界变化，P1 没落地 |
| 说不出来 | 这一拍对这孩子不存在 —— **无论 `stages_seen` 显示几段** |

**别问"你喜欢吗"。** 6 岁孩子会给让成人满意的答案；问"刚才发生了什么"才有信息。

**T3 收尾，门探针：**

> 「那扇门后面有什么？」

- 说得出来、且带着期待 → Day 6 的 anticipation 成立
- 「不知道」「打不开」→ 伏笔落空（对低完成度的孩子尤其要记下）

**T4（家长，5 分钟）：**

1. 「这一周孩子有没有主动把这个世界给别人看？」
2. 「有没有哪一天，孩子因为'世界没变化'而不再打开？」（追问具体是哪一天）
3. 家长 30 秒旁证（§3.3）

## 7. 分析前必须做的事

1. **按年龄带分开报。** 混龄数字只能放在附录。
2. **D8 是主指标**，D1–D7 是机制指标。阈值 30% 写死在
   `scripts/analyze-export.ts` 的 `D8_RETURN_FLOOR`，**不允许看完数据再调**。
3. 每一档少于 2 人**只报数、不判读**（脚本已经会拒绝判读，人工也别硬解释）。
4. 报告里明确区分：哪些结论靠**行为数据**，哪些靠**留存数据**，哪些只是**访谈印象**。
5. 「未回答」必须出现在 SAAR 分母里。看到 `selfInitiatedRate` 时先看
   `initiativeUnanswered` 有多大。

## 8. 判读卡（事先写下，事后只填数）

| 观测量 | 分叉 |
| --- | --- |
| **D8+ 回访率**（主） | < 30% → 「去掉代币后世界变化没撑住动机」；≥ 30% → 核心赌注成立的第一个证据 |
| D8 分档 | 某一档 0% 而总体达标 → 达标是那一档撑的，**报告必须点名** |
| 6–8 岁的 T0 提示率 / 家长介入率 | > 70% → 「6–8 岁需要成人脚手架模式」，而不是"不适合" |
| `stages_seen` 分档 + `skipped` | 6–8 岁显著更低或 skip 更高 → 先修反馈呈现，别去优化留存投放 |
| 学校类目标可信度信号 | 低龄段异常率高 → 「学校类目标在 6–8 岁不可用」是产品结论 |
| 门探针 | 低完成度孩子普遍答不出 → anticipation 只对高完成度成立，需要第二条轴 |
| Day 1 的 T1「卡在哪一步」 | 集中出现在同一处 → 那是可用性缺陷，不是动机问题 |
